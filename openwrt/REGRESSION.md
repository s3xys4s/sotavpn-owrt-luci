# Регресс Sota Gateway для Routerich AX3000

**2026-11-23.** Проверены `sota-gateway 0.1.0-r19` и `luci-app-sota 0.1.0-r15`. Для установки выберите комплект по версии OpenWrt. [Инструкция](ROUTERICH.md)

## Где проверено

- Сквозной тест прошёл на OpenWrt 25.12.6 в работающей паре ARM64 ВМ. Отдельный клиент получил адрес, маршрут и DNS через DHCP. Для HTTPS и UDP/STUN внешний IPv4 клиента сравнивался с независимо измеренными адресами WAN и TUN.
- Финальные пакеты для `aarch64_cortex-a53` установлены в свежие файловые системы официальных образов **Routerich AX3000** через `opkg` 24.10.8 и `apk` 25.12.6. Оба менеджера разрешили зависимости из штатных репозиториев. APK прошли проверку подписи. На обеих версиях запущены ядро, контроллер, ubus, rpcd, procd и uhttpd. После входа штатный uhttpd отдал все четыре страницы Sota в LuCI и их JavaScript. Правила DNS дополнительно проверены штатными SmartDNS 43 и 46.1 в отдельных сетевых пространствах имён.
- Сверены SHA-256 исполняемых файлов, службы, сетевой политики, адаптера rpcd, кнопок управления и меню на рабочем стенде и в обеих установках. Физический Routerich и фирменные модификации его прошивки в этом прогоне не участвовали.

## Результаты

| Область | Что прошло |
| --- | --- |
| Подписка и HWID | Обновление сохранило HWID и настройки. Загрузка списка серверов с действующей подпиской прошла. Ответы при принятом и отклонённом ключе дополнительно проверены с тестовым API. |
| Транспорт | VLESS, Hysteria2 и «Авто» дали ожидаемый VPN-IP для HTTPS и UDP/STUN. Свежие внешние DNS-запросы проходили при подключённом туннеле. |
| Остановка и отказ | Ручной «Стоп» снял политику, вернул клиенту WAN для HTTPS, UDP/STUN и DNS. После принудительного завершения ядра procd запустил новый процесс. Подключение восстановилось автоматически, клиент вышел с текущего IP туннеля. |
| Перезагрузка | Выполнены две полные перезагрузки виртуального OpenWrt. Активный туннель восстановился сам с сохранённым сервером и протоколом. После ручного «Стоп» клиент сохранил прямой WAN, включая UDP и DNS. Отдельно проверены остановка и запуск службы через init.d и запуск остановленной службы через RPC LuCI. |
| Сеть и DNS | Оба направления списков, ограничение по клиентскому IP, изменение DNS, выключение и включение политики, перечитывание firewall4. При выключении политики клиент вышел через WAN. С доступным link-local IPv6 DNS отвечал без политики и блокировался при включённой политике. |
| DNS over HTTPS | Клиентский запрос прошёл через TUN к выбранному резолверу по HTTPS. Недоступность DoH не привела к отправке запроса открытым текстом. В обоих образах штатный SmartDNS принял подходящий сертификат и отклонил сертификат для другого имени. Bootstrap получил только имя резолвера. |
| CIDR | Проверены `1.1.1.0/24`, перекрывающее исключение `1.1.1.1/32` и адреса вне списка. Реальный внешний IP подтвердил ожидаемый маршрут. |
| Домены | Проверены точное имя, wildcard, отрицательный пример с поддоменом и приоритет доменного исключения над CIDR. На обеих версиях SmartDNS проверены также несовпадения и перекрытие двух групп. |
| Предустановки | Адреса из действующих CIDR-списков YouTube и российских исключений найдены в соответствующих наборах nftables. Выданные клиенту DNS-адреса `youtube.com` и `vk.com` попали в соответствующие динамические наборы. |
| Источники | Ручные строки, TXT и две HTTP-ссылки объединились. Планировщик обновил маршруты и исключения и сохранил статический файл. После HTTP 503 рабочая копия сохранилась, доступный источник обновился. |
| Редактирование | Применение, удаление, возврат только встроенных списков, совместная видимость настроек в LuCI и стендовой панели. Неверный CIDR и устаревшая ревизия отклонены, сохранённые настройки остались рабочими. |
| Интерфейсы | В обеих панелях на ширине 375 пикселей три цветные кнопки расположились в один ряд. Проверены действия «Старт», «Стоп» и «Перезапуск». В Chrome открыты страницы LuCI на русском и английском, проверены поле HWID, диагностика IP, фильтр и пауза журнала, сеть, списки и исключения. В самой форме LuCI сохранены и перечитаны wildcard и TXT-файл объёмом свыше одного RPC-фрагмента. В стендовой панели проверены TXT, ссылки, черновики, язык, мобильная ширина. В отдельной Linux-копии проверены импорт профиля Shadowsocks, отказ транспорта и переподключение. |
| Комплектация | На чистой установке есть десять встроенных URL и файл российских исключений. rpcd обращается через Unix-сокет. Контроллер отклонил запуск отдельного веб-интерфейса даже с переменными включения. Порты 8080 и 18082 закрыты. Меню LuCI содержит подключение, сеть и DNS, списки и исключения. |

Порт 1053 закреплён за SmartDNS, dnsmasq слушает на 127.0.0.1:1054, а выделенный DoH-резолвер использует 127.0.0.1:1056. Несколько последовательных циклов удаления и возврата правила прошли с проверкой DNS с клиентского устройства. После прогона сверены исходная ревизия конфигурации и HWID, туннель подключён.

## Повторение

На выделенном хосте тестовой пары положите `openwrt_regression.py` и `egress_probe.py` рядом. Сценарий рассчитан на эксклюзивное использование стенда из `tools/openwrt_vm.sh`, уже подключённую тестовую подписку, встроенные списки и Python 3 на клиенте. Он временно меняет настройки и перезапускает тестовое ядро. Исходные параметры и содержимое списков восстанавливаются при выходе.

```sh
python3 openwrt_regression.py /var/lib/sota-wrt-lab
python3 openwrt_service_regression.py /var/lib/sota-wrt-lab
```

Браузерная проверка на выделенном стенде временно добавляет правило и файл, затем удаляет их. Она использует Node.js 22+, Chrome и автоматический выбор языка в LuCI. Путь к Chrome можно передать через `CHROME`, пароль тестового LuCI — через `LUCI_PASSWORD`.

```sh
node tools/openwrt_luci_regression.mjs http://192.168.1.88:8081/cgi-bin/luci/admin/services/sota/
```
