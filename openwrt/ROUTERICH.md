# Sota Gateway для Routerich AX3000

Комплект устанавливается поверх существующей OpenWrt. Управление находится в **Сервисы → Sota Gateway**. Отдельная веб-панель выключена на уровне сборки. На чистой установке LuCI обращается к контроллеру через rpcd и локальный Unix-сокет.

| Установленная прошивка | Менеджер | Проверенный комплект |
| --- | --- | --- |
| OpenWrt 25.12 | `apk` | 25.12.6, `mediatek/filogic`, `aarch64_cortex-a53` |
| OpenWrt 24.10 | `opkg` | 24.10.8, `mediatek/filogic`, `aarch64_cortex-a53` |

Версию показывает **Статус → Обзор**. В SSH её также показывает `ubus call system board`. Для фирменной прошивки RouteRich проверьте базовую версию OpenWrt и доступность репозиториев именно этой сборки. Модуль `kmod-tun` должен соответствовать установленному ядру.

## Установка

Распакуйте ZIP на компьютере. Скопируйте файлы одного комплекта в созданный вами каталог `/tmp/sota` на роутере. Проверьте свободное место командой `df -h /tmp /overlay`. Два исполняемых файла шлюза занимают около 42 МиБ в распакованном виде, установленные зависимости и пользовательские списки требуют дополнительного места.

**OpenWrt 25.12**

```sh
cd /tmp/sota
sha256sum -c SHA256SUMS &&
cp sota-lab.pem /etc/apk/keys/sota-lab.pem &&
apk update &&
apk verify ./sota-gateway-*.apk ./luci-app-sota-*.apk &&
apk add ./sota-gateway-*.apk ./luci-app-sota-*.apk
```

**OpenWrt 24.10**

```sh
cd /tmp/sota
sha256sum -c SHA256SUMS &&
opkg update &&
opkg install ./sota-gateway_*_aarch64_cortex-a53.ipk ./luci-app-sota_*_all.ipk
```

После успешной установки для обеих версий выполните

```sh
/etc/init.d/sota enable &&
/etc/init.d/sota start &&
/etc/init.d/firewall reload &&
/etc/init.d/rpcd restart
```

## Первое подключение

1. Откройте **Сервисы → Sota Gateway → Подключение**, введите ключ подписки и загрузите серверы.
2. В **Сеть и DNS** выберите входной интерфейс LAN, обычно `br-lan`. Для первой проверки можно указать IPv4 одного клиента в поле «Устройства, для которых действуют правила». Пустое поле распространяет политику на все устройства этого интерфейса.
3. В настройках межсетевого экрана выключите программную и аппаратную разгрузку потоков, если они включены. Сохраните настройки.
4. В разделе **Подключение** выберите сервер и протокол, нажмите зелёную кнопку **Старт**, затем **Проверить IP**. Виджет показывает IP для WAN и для туннеля.
5. В **Списках маршрутизации** выберите направление. **Исключения** всегда идут через WAN и имеют приоритет. Ручные строки, файлы и списки по ссылкам объединяются. Доменные правила используют IPv4 из ответов DNS шлюза. На выбранном LAN-интерфейсе политика блокирует транзит IPv6.

## Управление туннелем

Верхний ряд кнопок доступен на каждой странице Sota Gateway. **Старт** подключает выбранный сервер, применяет маршрутизацию и запоминает выбор для следующей загрузки. **Стоп** отключает туннель и возвращает клиентам штатную маршрутизацию и DNS OpenWrt. Ручная остановка сохраняется после перезагрузки. **Перезапуск** заново подключает выбранный сервер и протокол. Списки и настройки DNS сохраняются при всех трёх действиях.

Службой управляет procd. Команда `/etc/init.d/sota stop` временно останавливает службу. Команда `/etc/init.d/sota start` восстанавливает сохранённый режим, а `/etc/init.d/sota restart` перезапускает службу. Чтобы отключить и автозапуск, выполните `/etc/init.d/sota disable`. Вернуть автозапуск можно командой `/etc/init.d/sota enable`.

## DNS over HTTPS

В разделе **Сеть и DNS** укажите в поле **DNS over HTTPS** адрес резолвера, например `https://dns.google/dns-query`, и примените настройки. Поле **DNS через VPN** задаёт IPv4 резолвера для начального поиска адреса DoH-сервера. Затем внешние DNS-запросы клиентов отправляются по HTTPS через VPN с проверкой сертификата. Если DoH недоступен, запрос завершится ошибкой. Пустое поле DoH возвращает обычный DNS через VPN. Локальную зону обслуживает DNS OpenWrt.
